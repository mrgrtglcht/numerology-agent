# облачные публикации quantafate

github actions выполняет задачи без компьютера владельца. workflow `cloud.yml` использует уже настроенные github secrets, бесплатный gemini и buffer. платные поисковые API не добавлены.

## tiktok

ежедневная проверка очереди, максимум два ожидающих поста. один запуск создаёт одну исследованную часть серии, все семь изображений отправляются через `automatic + addToQueue`. время и дни определяет существующее расписание buffer, оно не изменяется. описание каждого поста содержит ссылку на канал https://t.me/quantafate. статус принятия в очередь не считается фактом публикации; история buffer сверяется отдельно.

## telegram

два самостоятельных подробных текстовых поста: среда и воскресенье в 18:30 Europe/Warsaw, с учётом летнего времени. 1400–3400 знаков для вводного поста, 1600–3400 — для отдельного аркана, источники и память тем. стиль опирается на https://t.me/quantafate/3 и `telegram_style.json`: строчные буквы, тёплое обращение на ты, простые объяснения и короткие абзацы. автоматическая реклама бота запрещена.

редакционный порядок telegram задаёт `telegram_series.py`: сначала общий пост о центре, затем отдельный подробный пост о каждом допустимом центральном аркане. после завершения — аналогичные серии о талантах, отношениях, профессии и общих значениях арканов. только подтверждённая отправка в telegram продвигает серию. неопределённая отправка блокирует продолжение этой темы; готовый предпросмотр переиспользуется, а не пересоздаётся. история tiktok не пропускает публикации telegram. для центра используются только числа из проверенного домена позиции I.

для каждого четвёртого текста модель может выбрать тематическое изображение; если подходящего нет, остаётся текст. картинка отправляется отдельно перед длинным текстом, поскольку стандартная подпись к фото ограничена 1024 знаками. обе операции учитываются в одной попытке; при неопределённом исходе повтор блокируется для ручной сверки.

## включение и контроль

репозиторные переменные `ENABLE_TIKTOK_CLOUD=true` и `ENABLE_TELEGRAM_CLOUD=true` управляют каналами независимо. удаление или значение false останавливает будущие задачи соответствующего канала, но не отменяет уже поставленные в buffer посты. старое расписание трёх тестовых карточек удалено.

ручные режимы: check (только подключения), preview (генерация без публикации), publish (явная отправка с разрешающей галочкой). расписание запускает scheduled. отправки сериализованы с другими задачами проекта. журнал дня создаётся до генерации; ошибки подготовки сохраняют план, источники и ответ модели в контрольной точке. следующий запуск продолжает тот же материал; после трёх неудач требуется проверка. потеря подтверждения отправки блокирует слепой повтор. предпросмотры используют отдельный журнал и не включают расписание сами.

история контента и квитанции хранятся в репозитории, результаты и изображения — также в артефактах на три дня. ключи в логи и журнал не попадают. неопределённая отправка tiktok останавливает пополнение очереди; telegram не отправляет тот же дневной пост повторно.

## изображения

для облачных арканов используются оригинальные изображения RWS, отмеченные Wikimedia Commons как public domain, с закреплёнными SHA-1 в `assets/tarot/public-domain-manifest.json`. сканы баннеров numerolog.ru остаются в прежнем режиме локальных макетов. соответствие матрице: 8 — справедливость, 11 — сила, 22 — шут. лицензии фонов проверяются, атрибуция при необходимости добавляется к подписи.

github actions может задерживать запланированный запуск. расписание — не гарантия отправки в точную минуту. ограничения бесплатных сервисов и отозванная авторизация могут остановить задачу; платного резервного сервиса и слепых повторов нет.

## восстановление подготовки

ответ модели запрашивается по JSON-схеме. проверка по-прежнему требует правильную тему, позицию, допустимые арканы и ссылки на подтверждённые источники. при некорректном ответе разрешён максимум один запрос исправления; ответ и факт запроса сохраняются между запусками. потерянный ответ повторно не запрашивается. бесплатный режим Gemini остаётся обязательным.

чтение источников, истории и состояния повторяется до трёх раз при временных сетевых ошибках. отправки в buffer/telegram и запросы модели автоматически не повторяются. потерянная квитанция buffer сверяется по тексту, каналу и числу изображений; неоднозначность оставляет отправку заблокированной.

похожие копии уже использованных картин отбрасываются по визуальным отпечаткам до выбора моделью. поисковые запросы меняются по дате задания, чтобы не ограничиваться первыми результатами.

все 22 прозрачные карты public domain поставляются вместе с проектом; контрольные суммы PNG закреплены в манифесте. облачная сборка не скачивает их с Wikimedia заново. повреждённый файл останавливает сборку, не подменяется другим изображением.

## короткие подписи и порядок частей

tiktok использует короткое название темы, номер части и только @quantafate. описание модели и прямой URL telegram в подпись не попадают. фоны для каруселей отбираются из public domain / CC0, без обязательной публичной атрибуции; исходники и лицензии сохраняются в журнале.

готовые неопубликованные части переиспользуются. активная серия имеет приоритет, перед отправкой проверяется наличие предыдущих частей в очереди или опубликованной истории. предпросмотр сам по себе публикацией не считается.
