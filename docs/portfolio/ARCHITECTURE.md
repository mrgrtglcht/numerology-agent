# устройство quantafate

[← обзор проекта](../../README.md)

## два самостоятельных компонента

**telegram-бот** принимает даты рождения, выполняет расчёты, строит png и отвечает на вопросы с помощью gemini. код бота находится в отдельном проекте: он не включён в этот репозиторий. его стек — python, aiogram 3, pillow, aiosqlite и httpx. арифметика отделена от ии-ответов; sqlite сохраняет состояние диалога. docker и systemd предназначены для размещения этого сервиса.

**контент-агент** находится в этом репозитории. он подбирает и продолжает темы, получает исследовательский контекст, готовит тексты, собирает изображения и управляет отправкой. для работы по расписанию используется github actions.

## цикл контента

1. редактор выбирает доступную тему или следующую часть незавершённой серии.
2. каталог определяет позицию матрицы, допустимые значения и охват частей.
3. исследовательский модуль получает выдержки из разрешённых источников или проверенной библиотеки. сохраняются происхождение и контрольные суммы.
4. gemini готовит текст в заданной структуре; программа проверяет ответ и соответствие источникам.
5. pillow собирает слайды из текста, схем, шрифтов и разрешённых изображений.
6. память связывает материал с темой, частью и готовыми форматами.
7. модуль отправки передаёт карусель в postwire или статью в telegram.
8. журнал отдельно фиксирует попытку отправки, принятие в очередь и подтверждённую публикацию.

telegram и tiktok имеют отдельные истории доставки. готовую часть можно переиспользовать без нового запроса к модели. неизвестный результат сетевой отправки не запускает слепой повтор.

## границы автоматизации

каталог реализует конкретную методику расчёта, а не все школы нумерологии. проверка структуры, ссылок и допустимых чисел не доказывает истинность интерпретаций. защита от повторов использует идентичность тем, хеши и близость текстов/изображений, а не гарантированное распознавание любого пересказа.

pinterest-формат готовится как набор изображений; автоматическая отправка многокарточных пинов не подтверждена. автодобавление музыки tiktok запрашивается через postwire; конкретный трек и охваты не гарантируются. лимиты и доступность внешних сервисов зависят от аккаунтов и тарифов.

## примеры и данные

изображение матрицы в readme построено настоящим рендерером бота для условной даты 01.01.2000. слайды взяты из подготовленной публичной серии проекта. пользовательские даты, переписка, база sqlite и ключи бота для оформления не публиковались.
