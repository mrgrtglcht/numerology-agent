# QuantaFate — минимальный агент

## Тематические серии по эскизу пользователя

`python agent.py series-auto --series-theme profession --part 0 --batch profession-01` создаёт всю серию одним запросом модели: обложка → схема с выделенной позицией → 4 аркана (карта слева, название и 2 абзаца справа) → спокойный финал про бота. `--part 1` рендерит только первую часть, а `--part 0` все части. Ответ модели сохраняется: следующую часть той же серии можно собрать без повторной генерации текста. Шрифт, строчные буквы и тёмные фоны сохраняются. CTA этого тематического формата включён согласно последнему запросу пользователя; хвосты остаются без обязательного CTA и без карт.

Темы: `profession` — точка FR денежного канала; `partner` и `meeting` — FL под сердцем; `talents` — C2 на верхнем луче; `centre` — I личной матрицы; `facts` — все 22 аркана без фиктивной позиции. `random` выбирает одну из этих зарегистрированных тем, стабильно для одного имени серии. Новая произвольная тема требует явной привязки к проверенной позиции; модель не назначает её сама. Место знакомства — возможная среда общения по символике, не предсказанный адрес.

`matrix_rules.py` вычисляет точные допустимые множества по тем же 32 формулам, что у `matrix-bot`, для личных дат 1900…9999 (не совместимость). В I невозможны 1, 2, 15, 17, 19, 21; в FR и FL допустимы 3…22; во внешнем C только 1…12. Поэтому профессии — 20 арканов в 5 частях, центр — 16 арканов в 4, факты — 22 аркана в 6. `series-plan.json` фиксирует все части; покрытие проверяется без пропусков/повторов. Образец схемы вычисляется по реальной допустимой дате-свидетелю, а не заполняется случайными числами. Отдельно прежний `carousel-auto` теперь отклоняет хвосты вне 26 арифметически достижимых сочетаний; порядок хвоста — G2–G1–G, от центра к нижней вершине. Другие методики и обратная запись автоматически не подмешиваются.

Карты берутся именно из центральной части больших баннеров numerolog.ru, выбранных пользователем, с чёрным контуром и прозрачными закруглениями. Локальные PNG лежат в `assets/tarot`; в облаке при необходимости загружаются баннеры по фиксированному манифесту с проверкой SHA-256. Исходные картинки и баннеры не коммитятся. Лицензия этих конкретных изображений на перепубликацию не установлена; новый режим сохраняет только предпросмотр. Сведения об источниках идут в `asset-notes.txt`. Фоны по-прежнему выбираются из лицензированных кандидатов Commons.

GitHub Actions: `series-auto`, выбрать `series_theme`, `series_part=0`, снять `demo_content` для настоящей генерации; разрешение публичной публикации оставить выключенным. Артефакт содержит `series.zip` и папки `part-01` и далее. При `--demo-content` работает только готовый пример профессий; это демонстрационные тексты, не новая генерация.

## Автоматическая карусель: поиск → модель → PNG

`python agent.py carousel-auto --topic "кармический хвост 15–5–8" --batch auto-15-5-8` ищет до восьми лицензированных фонов в Wikimedia Commons, передаёт их уменьшенные изображения Gemini и одним запросом получает выбор фонов, фокус кадрирования и пять содержательных слайдов. Программа добавляет обложку и оригинальную схему расположения хвоста, приводит текст к нижнему регистру, кадрирует изображения и накладывает затемнение. Готовы семь PNG 1080×1920, обзор, подпись, источники и архив. Другие сочетания задаются так же, например `18–6–6`; схема использует числа из темы.

Настройки Gemini прежние: `GEMINI_API_KEY`, `GEMINI_FREE_TIER_CONFIRMED=true`, `GEMINI_MODEL`. В GitHub Actions выбрать `carousel-auto`, указать тему, снять `demo_content`, оставить `approve_publication=false`. Результат скачивается в `quantafate-preview`; в соцсети этот режим не отправляет ничего. Поиск Wikimedia не требует отдельного ключа. Pinterest используется как направление эстетики, изображения с неизвестными правами оттуда автоматически не скачиваются.

`--demo-content` проверяет настоящие поиск и рендер на заранее написанном тексте 15–5–8 без Gemini; это отдельный демонстрационный тест, а не доказательство генерации. В живом режиме модель видит изображения и может отклонить все варианты. При недостатке подходящих материалов, неверном JSON или переполнении текста программа останавливается вместо выдачи случайного результата. Один запрос модели на серию, без платного резерва и автоматических повторов. Сохранённый ответ можно повторно отрендерить в той же серии без нового запроса; неопределённый незавершённый запрос не повторяется молча.

`sources.json` и `credits.txt` хранят автора, лицензию, ссылку и изменения каждого выбранного фона; эти файлы входят в архив. Для ручной публикации сохраняйте требуемую атрибуцию. Разрешены Public Domain/CC0 и поддерживаемые CC BY/CC BY-SA; другие лицензии отбрасываются. Manrope загружается с закреплённого коммита Google Fonts и проверяется по SHA-256; лицензия приложена. Присланные пользователем Pinterest-картинки не загружаются в публичный репозиторий.

## Карусель в согласованном стиле

`python agent.py carousel --batch style-15-5-8` собирает локальный образец: 7 PNG 1080×1920, превью, подпись и `carousel.zip`. Текст в `examples/15-5-8.json`; другой JSON передаётся через `--content`. Фоны лежат в `assets/backgrounds`, Manrope и его лицензия — в `assets/fonts`. Всё строчными, белый текст, пропорциональное кадрирование и затемнение, без карт таро и обязательной рекламы. На втором слайде оригинальная поясняющая схема, а не личный расчёт.

Этот режим работает без модели и не вызывает GitHub, Buffer, Telegram или Gemini (при первом запуске может понадобиться загрузка Manrope). Присланные пользователем фоны сохранены только локально для просмотра макета; права на их публикацию не подтверждены. Автопоиск и новая генерация находятся в отдельном `carousel-auto`. Прежние режимы `preview/draft/publish` пока используют прежний формат из трёх карточек: новый образец не переключает публикацию автоматически.

Генерирует короткие русские тексты через Gemini и рисует карточки Pillow. Создаёт Pinterest-пин с одной картинкой, TikTok-карусель с тремя картинками; отправляет пин с подписью в Telegram через Bot API. GitHub Actions запускает процесс, GitHub Secrets хранит ключи. Компьютер можно выключать после переноса в GitHub.

**Статус:** локальные проверки пройдены. Доставка в соцсети, Gemini и Telegram в этой сборке ещё не проверены. В Buffer Pinterest сейчас подключён, но список досок пуст даже после повторной авторизации. Пока можно независимо тестировать TikTok. Старый тест текстового Pinterest-черновика не имел изображения, поэтому его ошибка не доказывает, что полноценный пин не сработает.

## 1. Сначала без ключей и публикаций

Установите Python 3.12 или новее. В папке этой сборки:

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python agent.py demo
```

Результат — `output/<дата UTC>/`: три JPG 1080×1920, один JPG 1000×1500, текст `content.json`. Это исходный тестовый контент, не Gemini. На тестовых карточках есть отметка «ТЕСТ ФОРМАТА».

## 2. GitHub

Создайте отдельный **публичный** репозиторий `quantafate-agent` с README. Загрузите в его корень файлы из этой сборки вместе с `.github/workflows/agent.yml`, `tests/` и `.env.example`. Настоящий `.env`, output, __pycache__ и соседние проекты не загружайте.

Публичный репозиторий выбран для бесплатного исполнения стандартных Linux runners и прямых ссылок на JPG. Код, опубликованные для теста/постов карточки и журнал отправок будут публичными. Приватный репозиторий потребует отдельного публичного хранилища картинок; эта версия останавливается вместо раскрытия приватных файлов.

| --- | --- |

| GEMINI_API_KEY | Ключ проекта Gemini на Free tier |
| TELEGRAM_BOT_TOKEN | Токен Telegram-бота, который будет администратором канала |

**Variables** (обычные настройки, без секретов):

| Имя | Значение |
| --- | --- |
| BUFFER_TIKTOK_CHANNEL_ID | 6ad66ba9778b240e2f5d62dc |
| BUFFER_PINTEREST_CHANNEL_ID | 6ad66303778b240e2f5c7a0c |
| PINTEREST_BOARD_ID | 1141592274236006099 |
| TELEGRAM_CHANNEL_ID | @имя_вашего_канала или числовой ID канала |
| GEMINI_MODEL | gemini-3.5-flash-lite |
| GEMINI_FREE_TIER_CONFIRMED | true только после проверки Free tier в AI Studio |

`GITHUB_TOKEN` выдаётся GitHub автоматически для одного запуска; создавать личный токен для Actions не нужно. У workflow есть право `contents: write`, чтобы сохранять только готовые картинки и журнал. Если политика аккаунта запрещает запись, запуск остановится.

## 3. Тесты из Actions → QuantaFate → Run workflow

1. **check** — проверка доступа Buffer; только чтение.
   **telegram-check** — проверка токена Telegram, существования указанного канала и права бота публиковать. Использует только getMe/getChat/getChatMember; сообщений не отправляет, webhook и updates не затрагивает.
2. **demo** — исходные тестовые тексты и карточки без Gemini. Скачайте артефакт `quantafate-preview` и просмотрите JPG.
3. **draft**, targets `tiktok`, demo_content включён — сохранение трёх картинок по постоянным публичным HTTPS-ссылкам и создание черновика Buffer. Проверьте порядок карточек в Buffer, формат и доступность автоматической публикации. Черновик ничего не публикует.
4. **draft**, targets `pinterest`, demo_content включён — отдельный черновик пина с известным ID доски, даже если список досок Buffer пуст. Проверьте доску в самом черновике. Ошибка сохраняется в журнале, без секретов; не считайте её успешным тестом.
5. **publish** запускайте только после просмотра карточек: укажите нужную цель и включите approve_publication. Это **реальная публичная публикация**. Для Buffer приём запроса ещё не означает, что соцсеть получила пост: проверьте вкладку Sent/ошибки и сам TikTok/Pinterest. При ручном выборе Telegram бот отправит реальный пост в указанный канал. В режиме draft Telegram намеренно запрещён.
6. **preview**, demo_content выключен — один запрос к Gemini; проверьте текст и карточки в артефакте. При исчерпании квоты запуск остановится. Нет платного резервного сервиса, поиска или автоматических повторов.

Две цели можно передать через запятую: `tiktok,pinterest`. Разные режимы имеют разные журналы: черновик не мешает отдельному тесту публикации. В рамках одного режима повторный запуск в тот же день не отправляет второй экземпляр. Для новой намеренной локальной серии есть `--batch другое-имя`; в форме Actions такой обход специально не добавлен.

## 4. Расписание после успешных тестов

Укажите только проверенные каналы в `DAILY_TARGETS`, затем задайте `ENABLE_DAILY=true`. Раз в день Actions будет генерировать один набор через Gemini и отправлять его выбранным каналам. Это включает настоящую публикацию, без ручного подтверждения каждого запуска. Чтобы остановить — верните `ENABLE_DAILY=false`.

Расписание: **16:17 UTC** (18:17 в Варшаве летом, 17:17 зимой). Actions может задерживать запуск; точность до минуты не гарантируется. Workflow должен находиться в основной ветке. В публичных неактивных репозиториях GitHub может отключать расписания, следите за вкладкой Actions.

## Защита от повторов и ошибки

До каждого внешнего запроса отправки агент записывает `sending` в `ledger/<дата>-<режим>.json`. После принятия сохраняет ID поста/сообщения и статус `accepted`. Если связь оборвётся или процесс остановится, следующий запуск не повторит отправку вслепую: это может означать, что пост уже создан. Проверьте Buffer/Telegram и журнал. Статус `accepted` означает только принятие запроса; окончательную доставку Buffer нужно проверять отдельно.

HTTP-адреса, тела ошибок, заголовки и ключи в логи не выводятся. Не включайте отладку HTTP, `set -x` или печать окружения. В `media/` и `ledger/` сохраняется только сгенерированный публичный контент и квитанции отправки. Не передавайте модели секреты или личные данные.

## Бюджет

- [Buffer Free](https://buffer.com/pricing): до 3 каналов, до 10 постов одновременно в очереди на канал, 3000 API-запросов за 30 дней. Публикация `shareNow` не создаёт долгую очередь.
- [Gemini Free tier](https://ai.google.dev/gemini-api/docs/pricing): используйте бесплатный проект без платного биллинга. Флаг в коде — подтверждение владельца, он сам по себе не меняет тариф Google. Квоты зависят от проекта; при ошибке агент останавливается.
- [GitHub Actions](https://docs.github.com/en/actions/concepts/billing-and-usage): стандартные runners в публичных репозиториях бесплатны. Используется `ubuntu-latest`, без платных runners.
- Telegram Bot API и Pillow не требуют платной подписки. Отдельный сервер и платное хранилище не нужны.

Чтобы ограничить накопление медиа, периодически архивируйте старые JPG локально. Не удаляйте изображения, пока пост ожидает публикации. В этой версии автоматического удаления файлов нет. Публичные изображения после коммита могут сохраниться в истории Git.

## Форматы

[Buffer TikTok](https://support.buffer.com/en-us/articles/using-tiktok-with-buffer-oGEroY9Of2) допускает до 10 изображений, эта сборка отправляет 3 JPG. Музыку и эффекты эта версия не добавляет; возможности мобильного TikTok не полностью доступны через API. Pinterest получает один вертикальный JPG и конкретную доску, не карусель и не Idea Pin. [Buffer API](https://developers.buffer.com/guides/hosting-media.html) забирает файлы по публичным ссылкам, поэтому локальный путь или приватный артефакт Actions не подходит.


## фон каждого поста

одна карусель — одно изображение на всех слайдах. у каждой части свой фон; следующая серия использует новые изображения. общий журнал `state/background-history.json` хранится локально, а в GitHub Actions — в репозитории через GitHubStore. журнал общий для series-auto и carousel-auto, сохраняется до рендера и переживает перезапуск. совпадения по источнику, хешу файла и близкому визуальному хешу отклоняются. если новых подходящих фонов нет, сборка останавливается без повтора старого. повторный запуск той же части сохраняет её фон.


## память контента и pinterest

`state/content-memory.json` — общий журнал тем, позиции, арканов, части, смысловых единиц, хеша текста, готовых форматов и подтверждённых отправок по площадкам. записанные части и те же арканы в той же теме не генерируются под новым именем; смена фона или размера не создаёт новый пост. другая тема для того же аркана разрешена. при частично готовой серии выбираются оставшиеся части. random исключает исчерпанные темы. проверка выполняется до модели; после модели проверяются одинаковые и почти одинаковые тексты. это проверка структуры и близости слов, не гарантия распознавания любого смыслового перефразирования.

статусы различаются: reserved → prepared; отдельно draft, sending, accepted, needs_review, published для каждой площадки. accepted и scheduled не означают published. `sync_content_memory.py` только читает Buffer с полной пагинацией и записывает sent как подтверждённую публикацию. импорты идемпотентны. ошибки отправки не запускают повтор. посты, выложенные вручную вне Buffer, автоматически не обнаруживаются; их нужно добавить по ссылке/подтверждению владельца. журнал сохраняется локально и через GitHubStore в облачных запусках.

pinterest: отдельная композиция 1000×1500 (2:3), 2–5 карточек. для серии с четырьмя арканами обложка объединяется со схемой, четыре аркана идут отдельно, фраза про бота помещается на последней карточке. все арканы сохранены. файл `pinterest-series.zip` содержит пять подготовленных частей. это готовые изображения, не подтверждение автоматической отправки: старый Buffer-путь отправляет одиночный Pin и не объявляется поддержкой многокарточной карусели. создание карусели требует поддерживаемого бизнес-процесса Pinterest.

источники размеров: https://help.pinterest.com/en/business/article/pinterest-product-specs и https://help.pinterest.com/en/business/article/create-a-carousel .


## самостоятельный редактор

`python agent.py editor-auto --batch editor-example` выбирает незатронутую тему/часть, читает источники, готовит TikTok и Pinterest, сохраняет источники в метаданные и обновляет память. `--plan-only` выполняет только подбор темы и чтение интернета без Gemini и рендера. в workflow режим editor-auto при галочке «тестовый текст» работает как plan-only. публикация этим режимом не выполняется; расписание не включается.

справочник position_catalog.py содержит все 32 точки существующего личного бота, формулы, допустимые числа и статус трактовки. четыре дополнительные технические точки не получают выдуманных психологических значений. это одна методика личной матрицы, не все существующие школы, совместимость и годовые прогнозы.

topic_planner.py расширяет каталог до 53 направлений (6 исходных + 47 сочетаний подтверждённых позиций и смысловых углов). система сначала продолжает незавершённую серию, не повторяет занятые части и хранит стабильную идентичность позиции/угла/арканов независимо от заголовка. новые направления за пределами подтверждённого каталога не вводятся в публикацию без проверки.

web_research.py выполняет живое чтение AXVII и numerolog.ru, находит тематические гиперссылки на открытой странице, сверяет положение и читает значения нужных арканов. фиксирует дату, URL и SHA-256. источники — недоверенные данные; инструкции со страниц не выполняются. медицинские и событийные прогнозы исключаются из выдержек. каждое описание должно сослаться на источник позиции и собственного аркана, иначе сборка останавливается. source_ids подтверждают наличие основания, но не являются автоматической гарантией истинности каждой интерпретации.

никакие платные поисковые API и Google Search grounding не включены. один запрос Gemini для текста/выбора фона использует прежнюю проверку Free tier.
