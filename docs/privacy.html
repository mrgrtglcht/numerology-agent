для внутреннего инструмента quantafate publisher и этого сайта.

1. кто отвечает за данные

инструментом управляет владелец проекта quantafate. контакт для вопросов, запросов на доступ, исправление и удаление данных: @gewichte в telegram.

эта политика относится к подготовке и отправке контента через quantafate publisher. она не описывает обработку сообщений, дат рождения и расчётов в отдельном телеграм-боте quantafate.

2. текущее состояние приложения

это внутренний инструмент для собственного аккаунта владельца, без регистрации сторонних пользователей. он готовит изображения и тексты, ведёт историю контента и может читать историю подключённых каналов через buffer. прямое подключение pinterest находится в разработке и пока не действует.

после подключения pinterest планируется получать через официальную авторизацию идентификатор подключённого аккаунта, список его досок, идентификаторы и содержание собственных пинов, ссылки и статусы публикаций, а также токены доступа. пароли pinterest и данные чужих закрытых аккаунтов не запрашиваются.

3. какие данные используются и зачем

для подготовки контента используются темы, тексты, изображения, ссылки на открытые источники и сведения о лицензиях изображений. журнал хранит подготовленные материалы, их смысловые категории, контрольные суммы, даты, форматы и статусы отправки. это позволяет продолжать серии и предотвращать повторы.

из buffer читаются тексты, идентификаторы и статусы постов, ссылки на публикации и время отправки в настроенных каналах владельца. в будущем собственные пины pinterest будут использоваться для аналогичной проверки истории, а доски — для выбора места публикации.

для генерации через google gemini передаются тема, выдержки из открытых источников, уменьшенные изображения кандидатов на фон и краткая история контента. токены доступа и пароли не включаются в запросы к модели. личные даты рождения пользователей телеграм-бота для этих каруселей не требуются.

4. хранение и доступ

рабочие файлы хранятся на компьютере владельца и в github. текущий репозиторий проекта публичный: журнал контента, тексты подготовленных материалов, идентификаторы постов и несекретные квитанции отправки могут быть доступны любому посетителю. в эти файлы не следует помещать закрытые сообщения и иные конфиденциальные данные.

ключи сервисов в текущей настройке хранятся отдельно — локально в файле окружения и в github actions secrets. они не предназначены для публикации в репозитории или на этом сайте. механизм хранения будущих токенов pinterest должен быть реализован до запуска прямого подключения; эта политика будет обновлена при изменении обработки данных.

журнал контента сохраняется, пока нужен проекту для предотвращения повторов; автоматический срок удаления сейчас не установлен. файлы результатов github actions настроены на хранение в течение трёх дней. опубликованные материалы, их копии и история git могут сохраняться дольше.

5. используемые сервисы

github используется для кода, выполнения задач, хранения истории и, при размещении сайта на github pages, его показа. google gemini обрабатывает запросы генерации. buffer и подключённые социальные платформы обрабатывают контент и сведения о публикациях при использовании соответствующих функций. при прямом подключении pinterest данные будут передаваться pinterest через его официальный api.

эти сервисы обрабатывают данные по собственным условиям; инфраструктура может находиться в разных странах. quantafate publisher не предназначен для продажи данных или передачи их рекламным сетям.

6. посещение сайта

в коде этого сайта нет аналитики, рекламных скриптов, форм сбора данных или собственных cookies. при размещении на github pages github регистрирует ip-адрес посетителя для безопасности согласно своей политике конфиденциальности. переход по ссылке в telegram регулируется также правилами telegram.

7. отключение и удаление

владелец может остановить задачи приложения и отозвать доступ подключённых сервисов в их настройках. после реализации прямой интеграции pinterest отключение и отзыв доступа будут проверены до её рабочего запуска.

для запроса на доступ, исправление или удаление относящихся к вам данных напишите @gewichte, указав затронутую публикацию или запись, без отправки паролей и токенов. запрос будет рассмотрен с проверкой принадлежности данных. удаление рабочих файлов не гарантирует удаления публичных копий, истории git и опубликованных пинов; публикации и доступ к ним также управляются средствами соответствующей платформы.

8. изменения

при изменении подключений, состава данных или способа хранения эта страница обновляется. дата актуальной редакции указана вверху.
